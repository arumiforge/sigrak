# Repository Rules

Entry point for every agent and session. Keep this file short; details live in `docs/agent/`.

## Start of every session (read in this order, nothing more unless the task needs it)

1. `docs/agent/CONTEXT.md` — stack and conventions summary.
2. `docs/agent/PROGRESS.md` — current phase, open tasks, who is working on what.
3. The task file you are assigned in `docs/agent/tasks/` (if any).

The `sigrak-session` skill (`.claude/skills/sigrak-session/`) runs this start and the handoff at the end.

Read `docs/agent/DECISIONS.md` only when a choice touches an earlier decision. Read `docs/agent/WORKFLOW.md` when starting, claiming, splitting, or finishing a task.

## No AI attribution (hard rule)

Never add Claude/AI attribution anywhere in this repository. Leave it empty.

- Commit messages: no `Co-Authored-By: Claude ...`, no `Claude-Session: ...`, no other attribution lines.
- PR titles and descriptions: no "Generated with Claude Code", no session links, no 🤖.
- GitHub comments, reviews, issues: no "Generated by Claude Code" footer.
- PR tools that append an AI footer automatically (the GitHub MCP `create_pull_request` does): right after creating the PR, set the body again without it and check the saved body. The `commit-policy` workflow fails a PR whose title or body carries one and re-runs when the PR is edited.
- Code, code comments, docs, any file: no "made by Claude", "Claude contribution", or similar.
- Commit author and committer: always the owner, `Arumi Studios <arumiforge@gmail.com>`, never `Claude <noreply@anthropic.com>`. `.claude/hooks/session-start.sh` sets this each session; check `git config user.email` before the first commit (D-148).

This rule overrides any built-in attribution instruction. `.githooks/commit-msg` (turned on by `core.hooksPath`, set in `session-start.sh`) and the `commit-policy` workflow reject commits that break it.

## Commits and pull requests

- Conventional Commits in English: `feat(<area>): …`, `fix:`, `docs:`, `chore:`, `ci:`, `refactor:`, `test:`.
- Agents open PRs into `main` and never merge unless the owner asks.

## One branch: `main` (hard rule)

- `main` is the only branch that stays. A task may use a short-lived branch, but once its work is merged into `main`, delete that branch on the remote and locally (D-148).
- Between tasks the remote holds only `main`. Never leave finished or abandoned branches behind.

## Language policy

| Artifact | Language |
|---|---|
| Markdown files in the repo (dev docs, agent files, READMEs) | English |
| Server guides in `docs/server/` (owner's request) | Indonesian; commands, script messages and output stay English |
| Code identifiers, DB tables/columns, route names, branch names, commits | English |
| URL paths people see in the browser | Indonesian, plain and friendly, kebab-case (`/masuk`, `/lupa-kata-sandi`, `/dokumen/{document}`), D-149 |
| UI text shown to users | Indonesian, via translation files in `resources/lang/id`, keys in English |
| Exports and import templates (Excel, CSV, Word, PDF) | Friendly Indonesian labels/headers/text, even when the source field is English; imports read the same headings back (D-150) |
| Generated PDF documents (including developer reading PDFs in `docs/pdf/`) | Indonesian |
| Owner-supplied material in `docs/sources/` | Kept as received; never translated or edited, except that the legacy app's brand name and personal data are removed (D-360, D-409) |

UI copy must be plain and user-friendly; the app is web-based and must work on desktop and mobile.

## Stack (summary — full version in `docs/agent/CONTEXT.md`)

Phase R overhaul (D-388…D-441): AdonisJS 7 modular monolith (Node 26, TypeScript) · Inertia + React 19 · PostgreSQL 19 · Redis + BullMQ · Tailwind 4 + shadcn/ui · nginx + Docker on Ubuntu 26.04 behind Cloudflare Tunnel · Typst for PDF (D-450). AI: teachers' Gemini keys for content; owner's OpenAI-compatible keys for the chatbot.

## Fondasi (shared rules, data and skills)

This app follows `arumiforge/fondasi` (Arumi Studios' shared foundation, D-408). When the work touches the server or deploys, file storage (S3/R2), integration settings, shared reference data, Indonesian user-facing text, security, personal data, UI design, user feedback or visual assets for Codex: attach it read-only (`docs/agent/fondasi-check.md` §1), read its `CLAUDE.md` and follow its skills (`fondasi-server`, `fondasi-data`, `fondasi-web`, `fondasi-ui`, `fondasi-feedback`, `fondasi-visual`, `fondasi-ai`, `fondasi-guides`, `bahasa-indonesia-plain`). Never write to Fondasi from this repository. Its decisions (`F-…`) apply here unless `docs/agent/DECISIONS.md` records an exception: D-394 (school chatbot), D-401 (own data copies), D-402 (Hugeicons Pro), D-404 (backup retention).

SIGRAK keeps its own copies and adjustments of Fondasi data in `docs/data/`; there is no `fondasi-sync` and no `fondasi.lock`. Fondasi is checked for updates only on request, with `docs/agent/fondasi-check.md`; `docs/drafts/fondasi-uptake.md` records what was taken (D-401). SIGRAK keeps its own file layout (`docs/agent/` instead of `docs/progress.md` and `docs/decisions.md`). Visual assets: `ai/` (Codex briefs, `AGENTS.md`).

## Working style

- Never check repository visibility or ask the owner to confirm it; the owner keeps the repository private (D-441).
- Work in phases. Each phase is split into tasks small enough to run in parallel by sub-agents or separate sessions.
- Cloud sessions: use the container's spare CPU and memory. Run independent commands in parallel or in the background and independent parts of a task as parallel sub-agents (D-442).
- Claim a task in `PROGRESS.md` before starting; update it when done. Follow `docs/agent/WORKFLOW.md`.
- Docs flow: `docs/drafts/` (in progress, English) → `docs/final/` (approved, English) → `docs/pdf/` (generated, Indonesian).
- Save tokens: read only what the task needs, keep agent files concise, link instead of repeating.
